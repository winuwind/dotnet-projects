# SOCKS5 Proxy Server

Реализация прокси-сервера, соответствующего стандарту **SOCKS5 (RFC 1928)**, выполненная на C#.

---

## Описание

Программа поднимает SOCKS5-прокси на указанном порту и перенаправляет TCP-трафик между клиентом и целевым сервером.

Поддерживаются все команды:

* `0x01`: establish a TCP/IP stream connection
* `0x02`: establish a TCP/IP port binding
* `0x03`: associate a UDP port

Аутентификация не реализована согласно условиям.

Вся обработка соединений осуществляется **в одном потоке** с использованием механизма **селектора** (Socket.Select()).
Холостые циклы отсутствуют.

---

## Возможности

* Полная поддержка всех команд **SOCKS 5 Proxy**
* Передача данных в обе стороны (client ↔ remote)
* **Доменный резолвинг (ATYP = 0x03)** через UDP-DNS
* Отдельный UDP-сокет для DNS-запросов, тоже в неблокирующем режиме
* Корректное завершение TCP-соединений
* Защита от неограниченного потребления памяти одним клиентом
* Производительность, сопоставимая с прямым подключением
* Поддержка адресов IPv6

## Логика работы

### 1. Установление SOCKS5-соединения

1. Клиент подключается и отправляет список поддерживаемых методов аутентификации.
2. Сервер отвечает методом `0x00` (без аутентификации), если клиент поддерживает данный метод. Иначе, клиент получает `0xFF`, и соединение закрывается.
3. Клиент отправляет SOCKS5-запрос.

### 2. Обработка адреса

Сервер:

* определяет тип адреса:

    * IPv4 (`0x01`)
    * доменное имя (DNS) (`0x03`)
    * IPv6 (`0x04`)
* при необходимости выполняет DNS-запрос для получения адреса

### 3. Обработка команды

Сервер:

* Определяет тип команды:
    * `0x01`: establish a TCP/IP stream connection
    * `0x02`: establish a TCP/IP port binding
    * `0x03`: associate a UDP port 

* Если команда `0x01`:
    * создаёт удалённое TCP-подключение
    * отправляет клиенту ответ с успехом (или ошибкой), и адресом с портом, с которых сервер установил соединение

* Если команда `0x02`:
    * создаёт TCP-сокет и начинает слушать на свободном порту
    * отправляет клиенту ответ с успехом (или ошибкой), и адресом с портом, на котором ожидает соединения

* Если команда `0x03`:
    * создаёт UDP-сокет, на который ожидает сообщения

### 3. Проксирование данных

После установления соединения сервер:

* Если команда `0x01`:
    * добавляет оба сокета в селектор
    * передаёт данные между ними
    * закрывает соединение, только когда обе стороны завершили передачи

* Если команда `0x02`:
    * слушает до первого подключения на новом сокете
    * отправляет клиенту информацию о подключении
    * добавляет сокеты клиентов в селектор
    * передаёт между ними данные
    
* Если команда `0x03`:
    * добавляет UDP-сокет в селектор
    * полученные от клиента данные пересылает на сервер, адрес которого указан в полученный байтах
    * полученные данные от любого другого источника пересылает клиенту
    * отправления происходят через тот же UDP-сокет

### 4. DNS

Для доменных имён:

* формируется A-запрос вручную
* запрос отправляется через UDP-сокет

## Как запустить

### Сборка

```bash
dotnet build
```

### Запуск

Укажите порт, например `1080`:

```bash
dotnet run -- 1080
```

SOCKS5-прокси будет принимать подключения на адресах, которые отобразит после запуска.

Для просмотра порта введите команду `port`, для просмотра ip - `ip`, для просмотра доменного имени - `dns`.

Для завершения программы введите `exit`, или нажмите `Ctrl+C` и `Enter`

---

## Особенности реализации

* Один поток обработки работы с сокетами
* Нет холостых циклов — каждая итерация селектора делает реальную работу
* Ограниченные буферы для защиты от DoS
* Полная поддержка duplex-streaming
* Собственный обработчик DNS-ответов

## Примечания

* Требуется .NET 9
